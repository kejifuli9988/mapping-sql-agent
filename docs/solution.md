# 智能体方案说明

## 一、题目理解

题目本质上要求设计一个面向数据开发的智能体，把“人工阅读 Mapping 文档并编写 SQL”的过程自动化，同时把行内数据中台规范嵌入到生成链路中，减少编码错误、评审成本和文档代码不一致问题。

## 二、方案定位

本项目实现的是一个 `Mapping -> SQL` 的本地智能体原型，强调三点：

1. `Mapping` 文档是唯一输入源。
2. SQL 生成时自动套用统一规范。
3. 生成后立即执行规则校验，便于开发和评审。

## 三、智能体架构

### 1. 输入层

输入为结构化 Mapping 文档，当前采用 JSON 表达，后续可以扩展为 Excel、Markdown、Word 解析结果。文档中包含：

- 目标表
- 分区信息
- 来源表
- Join 关系
- 过滤条件
- 目标字段及映射表达式

### 2. 推理与生成层

`SQLGenerator` 负责将 Mapping 文档转换为 SQL。当前使用规则驱动方式完成：

- 自动生成 `WITH` 分层
- 自动拼接 `INSERT OVERWRITE TABLE`
- 自动生成 `SELECT`
- 自动拼接 `JOIN / WHERE / GROUP BY`

这样做的优势是稳定、可控、便于审计，适合作为行内场景的落地底座。

### 3. 规范控制层

`SQLStyleChecker` 负责对生成结果做统一校验，例如：

- 是否包含核心 SQL 结构块
- 目标表是否小写
- 主查询是否错误使用 `SELECT *`
- 是否遗漏分号
- 有聚合时是否遗漏 `GROUP BY`

### 4. 编排层

`MappingSQLAgent` 负责串联整条链路：

1. 解析 Mapping
2. 生成 SQL
3. 检查规范
4. 输出结果

## 四、如何解决题目中的三个痛点

### 1. 解决“编码效率低且质量难保障”

人工写 SQL 需要开发人员来回对照需求、Mapping 和 SQL，容易出现字段拼写、类型不一致、逻辑遗漏等问题。

本方案中：

- 开发人员只需要提供 Mapping 文档
- 系统自动生成标准 SQL 骨架和字段映射
- 规范检查器自动发现常见结构性问题

这能显著减少重复编码和低级错误。

### 2. 解决“Mapping 更新后 SQL 难同步”

因为 Mapping 是唯一输入源，当业务规则或字段发生变化时，只需更新 Mapping 再重新生成 SQL，即可避免“文档一套、代码一套”的问题。

### 3. 解决“相似业务逻辑无法复用”

通用的数据开发模式，例如：

- 明细到汇总
- 多表 Join
- 维度聚合
- 同比环比扩展

都可以在同一个生成框架下复用，不需要每次从头编写 SQL。

## 五、项目当前能力

当前版本已经实现：

1. 根据 Mapping 文档生成 SQL
2. 按统一规范输出 SQL
3. 生成后执行基础规范检查
4. 提供示例 Mapping 文档和命令行运行方式

## 六、建议在答辩时强调的亮点

1. 这是一个“以 Mapping 为单一事实来源”的智能体，而不是简单的脚本生成器。
2. 智能体把“生成”和“校验”合并在一条链路里，更贴近真实数据中台研发流程。
3. 当前版本先采用规则优先，便于行内可控落地；未来可叠加大模型能力处理更复杂的业务口径和自然语言规则。

## 七、后续演进方向

1. 支持 Excel Mapping 文档导入。
2. 增加字段类型校验、目标表血缘校验、重复字段校验。
3. 接入大模型，对复杂业务规则进行自动补全和解释。
4. 自动识别 Mapping 变更并生成 SQL 差异。
5. 对接代码仓库和评审平台，形成自动评审闭环。
